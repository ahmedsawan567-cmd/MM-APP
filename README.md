# M M Application - Loyalty API (نظام ولاء المتاجر والمول)

مشروع الباك إند (Backend) المتكامل لمنظومة ونظام ولاء المتاجر والمول، مبني باستخدام **ASP.NET Core Web API (.NET 9)** مع **Entity Framework Core** و **SQL Server** و **JWT Authentication** وفق معمارية **Clean & Modular Architecture**.

## 🧭 خريطة الـ Endpoints في النظام:

### 1. المصادقة والحسابات (`/api/auth`):
- `POST /api/auth/register`: إنشاء حساب عميل جديد ومحفظته فوراً.
- `POST /api/auth/login`: تسجيل الدخول وإصدار توكن JWT.
- `GET /api/auth/me`: استعلام الملف الشخصي ورصيد المحفظة (`[Authorize]`).

### 2. الفواتير والتعرف الذكي (`/api/invoices`):
- `POST /api/invoices/upload`: رفع صورة الفاتورة، استخراج البيانات، احتساب النقاط وتحديث المحفظة (`[Authorize]`).
- `GET /api/invoices`: استعراض الفواتير (`[Authorize]`).
- `GET /api/invoices/{id}`: استعلام فاتورة محددة (`[Authorize]`).

### 3. المكافآت واستبدال النقاط (`/api/rewards`):
- `GET /api/rewards`: استعراض كتالوج المكافآت والعروض المتاحة.
- `GET /api/rewards/{id}`: تفاصيل مكافأة معينة.
- `POST /api/rewards`: إضافة مكافأة جديدة (`[Authorize(Roles = "Admin")]`).
- `POST /api/rewards/{id}/redeem`: استبدال النقاط وإصدار قسيمة خصم بكود فريد `MM-XXXXXX` (`[Authorize]`).

### 4. المحفظة والقسائم (`/api/wallet`):
- `GET /api/wallet/summary`: ملخص المحفظة والنقاط والقسائم النشطة (`[Authorize]`).
- `GET /api/wallet/transactions`: سجل حركات النقاط التفصيلي (`[Authorize]`).
- `GET /api/wallet/my-vouchers`: قسائم وكوبونات العميل (`[Authorize]`).
- `POST /api/wallet/vouchers/{code}/validate-and-use`: فحص وتطبيق القسيمة عند الكاشير (`[Authorize(Roles = "Admin,Merchant")]`).

### 5. لوحة تحكم الإدارة (`/api/admin` - `[Authorize(Roles = "Admin")]`):
- `GET /api/admin/dashboard/metrics`: إجمالي المبيعات، العملاء، الفواتير، والنقاط المصدرة والمستبدلة.
- `GET /api/admin/dashboard/top-merchants`: المتاجر الأكثر مبيعات وفواتير.
- `GET /api/admin/dashboard/recent-activity`: خلاصة أحدث العمليات.
- `GET /api/admin/invoices/pending`: الفواتير المعلّقة للمراجعة.
- `POST /api/admin/invoices/{id}/approve`: اعتماد فاتورة معلّقة وإضافة نقاطها.
- `POST /api/admin/invoices/{id}/reject`: رفض فاتورة معلّقة مع ذكر السبب.
- `POST /api/admin/customers/{id}/adjust-points`: تعديل رصيد النقاط إدارياً (إضافة أو خصم).
- `GET /api/admin/customers`: إدارة وبحث العملاء.

## 🤖 قراءة الفواتير بالذكاء الاصطناعي (Gemini)

تُقرأ صور الفواتير (JPG / PNG / WEBP / PDF) بـ Google Gemini: المتجر، رقم الفاتورة، الرقم الضريبي، التاريخ، المبلغ، الأصناف، ومطابقة المتجر مع متاجر المول، مع رصد علامات التلاعب. نفس المحرك يتعلّم "بصمة" فاتورة كل متجر في صفحة نماذج الفواتير.

1. أنشئ مفتاح API من https://aistudio.google.com ← **Get API key**.
2. احفظه على جهازك (لا تكتبه في `appsettings.json`):
   ```bash
   cd src/MMApplication.Api
   dotnet user-secrets set "Gemini:ApiKey" "AIza..."
   ```
   أو على الخادم كمتغير بيئة: `GEMINI_API_KEY`.
3. أعد تشغيل الـ API. ستظهر في صفحة **مراجعة الفواتير** عبارة "القراءة بواسطة Gemini".

- النموذج الافتراضي `gemini-flash-latest` (أحدث نموذج Flash دائماً). لتثبيت نموذج: `dotnet user-secrets set "Gemini:Model" "..."`. إن لم يتوفر النموذج لمفتاحك تختار المنظومة أحدث نموذج Flash متاح تلقائياً.
- **مجاناً:** مفتاح Google AI Studio بدون تفعيل الفوترة يعمل على نماذج Flash وFlash-Lite المجانية (بحد يومي للطلبات). عند انتهاء حصة النموذج الأساسي تنتقل المنظومة تلقائياً إلى `gemini-flash-lite-latest` (حصته منفصلة). لتعطيل ذلك: `Gemini:FallbackModel` = `none`.
- **إعادة القراءة التلقائية:** إن انتهت الحصة المجانية أو تعطلت الخدمة لا تضيع الفاتورة: تُحفظ للمراجعة وتُعاد قراءتها تلقائياً (بعد 5 د، 15 د، 30 د، 1 س، 2 س، 4 س، 8 س، 12 س). إن نجحت القراءة ولم يوجد سبب للمراجعة تُعتمد وتُضاف النقاط ويصل الإشعار للعميل.
- إذا ظهر سبب "غير متاحة من البلد الذي يعمل منه الخادم": Gemini API غير مفتوح في كل الدول؛ شغّل الخادم على استضافة في دولة مدعومة.
- Claude ما زال مدعوماً كبديل: `Claude:ApiKey` (يُستخدم إن لم يوجد مفتاح Gemini)، أو اختر صراحة بـ `"OcrProvider": "Claude"`.

بدون مفتاح يعمل محرك تجريبي وهمي (للتطوير فقط)، وخارج بيئة التطوير تُحوّل كل فواتيره للمراجعة اليدوية ولا تُمنح نقاط تلقائياً.

**متى تُعتمد الفاتورة تلقائياً؟** إذا كانت فاتورة شراء حقيقية، من متجر داخل المول، بثقة قراءة ≥ 85%، بدون ملاحظات تلاعب، بتاريخ حديث، بالدينار الليبي، وبمبلغ أقل من 3000 د.ل. غير ذلك تذهب لشاشة **مراجعة الفواتير**. الحدود قابلة للتعديل في قسم `InvoiceReview` في `appsettings.json`.

## 🛡️ أسس الحماية والهوية

- **رقم عضوية مميز** لكل عميل (MM-100001…) يظهر في التطبيق (بطاقة العضوية + QR) وفي المنصة، ويُبحث به.
- **رقم الهاتف لا يتكرر**: يُوحَّد قبل الحفظ (0912345678 = +218912345678 = 00218 91 234 5678).
- **رقم الفاتورة يُستخدم مرة واحدة لكل متجر**: يُوحَّد (بدون مسافات/رموز/أصفار بادئة) ويحميه فهرس فريد في القاعدة. أي محاولة تكرار تُرفض فوراً وتُسجَّل في سجل العمليات (مع تمييز محاولات الحسابات الأخرى).
- **نماذج الفواتير**: من صفحة "نماذج الفواتير" ارفع صورة فاتورة من كل متجر، فيستخرج Claude بصمتها (الاسم المطبوع، الرقم الضريبي، تسمية رقم الفاتورة ومثاله ونمطه). تُستخدم مع كل فاتورة يصورها العميل، والفاتورة المخالفة للنمط أو للرقم الضريبي تُحوَّل للمراجعة.
- **حد يومي** لعدد الفواتير لكل عميل، وحدود القبول التلقائي، كلها من صفحة الإعدادات.
- العميل يعدّل بياناته ويغيّر كلمة مروره ويحذف حسابه من التطبيق؛ الموظفون يعدّلون أي بيانات للعميل ويعيدون ضبط كلمة مروره من المنصة.

## 🔔 الإشعارات

- **المنصة:** جرس في الشريط العلوي يُحدَّث كل 30 ثانية: فاتورة تحتاج مراجعة، اعتراض عميل، إعادة تصوير، محاولة استخدام فاتورة مكررة. يمكن تفعيل تنبيهات المتصفح ليصل التنبيه حتى لو كانت الصفحة في الخلفية.
- **التطبيق:** صندوق إشعارات وجرس بعدد غير المقروء. أول مرة بعد الدخول يُطلب إذن الإشعارات. يفحص التطبيق الإشعارات الجديدة في الخلفية كل ~15 دقيقة (حتى لو كان مغلقاً) ويُظهرها على الهاتف: اعتماد/رفض/إلغاء فاتورة، طلب إعادة تصوير، تعديل النقاط، وإعلانات المول.
- **أثناء فتح التطبيق:** كل 30 ثانية (وعند الرجوع للتطبيق) تظهر الإشعارات الجديدة على الهاتف.
- **إرسال إشعار للعملاء وسجل المرسل:** صفحة **الإشعارات المرسلة**: إرسال لكل العملاء أو لشريحة، عدد المستلمين ومن قرأ، إعادة الإرسال، وسحب الإشعار من التطبيقات.

### إشعارات فورية والتطبيق مغلق (Firebase — مجاني)
1. https://console.firebase.google.com ← أنشئ مشروعاً ← أضف تطبيق Android باسم الحزمة `ly.mmapp.almaraamall` ← نزّل `google-services.json`.
2. **التطبيق:** في GitHub ← Settings ← Secrets and variables ← Actions ← New repository secret باسم `GOOGLE_SERVICES_JSON` والصق محتوى الملف كاملاً، ثم أعد بناء الـ APK (Actions ← Android APK ← Run workflow).
3. **الخادم:** Firebase ← Project settings ← Service accounts ← Generate new private key ← احفظ الملف في جهاز الخادم (خارج مجلد المشروع) ثم:
   ```bash
   cd src/MMApplication.Api
   dotnet user-secrets set "Firebase:ServiceAccountPath" "C:\MMApp\firebase-service-account.json"
   ```
   أعد تشغيل الخادم؛ تظهر "Firebase مفعّل" في صفحة الإشعارات المرسلة. ملف حساب الخدمة سرّي: لا يُرفع للمستودع ولا يُرسل لأحد.

بدون Firebase يعمل كل شيء كما هو (فحص دوري)، لكن وصول الإشعار والتطبيق مغلق قد يتأخر حسب نظام أندرويد.

## 👥 مستخدمو المنصة (طاقم العمل)

| الدور | ماذا يرى ويفعل |
|---|---|
| **المدير العام** (Super Admin) | كل شيء، وهو الوحيد الذي يدير حسابات الطاقم والصلاحيات |
| **مدقق فواتير** (Auditor) | مراجعة الفواتير وقبولها/رفضها، تدقيق الاحتيال، الاطلاع على القسائم |
| **مدير متجر** (Store Manager) | بيانات متجره فقط (فواتيره، تقاريره، قسائمه) |
| **كاشير** (Cashier) | التحقق من قسائم العملاء وصرفها في متجره |

- الإضافة من **المنصة ← طاقم العمل ← إضافة مستخدم جديد**: زر **توليد** ينشئ كلمة مرور قوية، وتظهر بيانات الدخول مرة واحدة لتسليمها للموظف.
- الموظف يدخل برقم هاتفه وكلمة المرور على `/AdminDashboard/Login`.
- **نسيت كلمة مرور المدير العام؟** أوقف الخادم ثم شغّله مرة واحدة بالخيار:
  ```bash
  dotnet run -- --Bootstrap:ResetAdminPassword=true
  ```
  تظهر كلمة مرور جديدة للحساب `admin` في السجل (ويُفعَّل الحساب إن كان معطلاً). بعدها أوقفه وشغّله بالأمر العادي، وغيّر كلمة المرور من صفحة طاقم العمل.
- كلمات مرور الموظفين الآخرين يعيد ضبطها المدير العام من زر التعديل في صفحة طاقم العمل. العملاء يسجلون حساباتهم بأنفسهم من التطبيق.
- مدير المتجر والكاشير يجب ربطهما بمتجر. لا يمكن حذف/تعطيل حسابك الحالي ولا آخر مدير عام. يفضّل **التعطيل** بدل الحذف للحفاظ على السجل.


للهاتف الحقيقي: شغّل الخادم ليستمع على الشبكة (`dotnet run --urls http://0.0.0.0:5000`)، واعرف عنوان جهازك من `ipconfig` (IPv4)، واسمح بالمنفذ 5000 في جدار حماية Windows عند السؤال.
صور الفواتير التي يرفعها العملاء تُقرأ بـ Claude وتُحفظ في `src/MMApplication.Api/wwwroot/uploads`، وتظهر في شاشة المراجعة باللوحة.

## 🗄️ ربط قاعدة البيانات (Supabase / PostgreSQL)

بدون رابط اتصال يعمل الخادم على **قاعدة مؤقتة في الذاكرة** (تُمسح عند إعادة التشغيل، وتظهر شارة صفراء في لوحة التحكم).

1. من Supabase: زر **Connect** أعلى المشروع ← **Session pooler** ← انسخ الرابط (`postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-....pooler.supabase.com:5432/postgres`) وضع كلمة المرور مكان `[YOUR-PASSWORD]`.
   (الرابط المباشر `db.xxxx.supabase.co` يعمل فقط على شبكات IPv6، لذلك نستخدم Session pooler.)
2. احفظه على جهازك (لا تكتبه في الكود):
   ```bash
   cd src/MMApplication.Api
   dotnet user-secrets set "ConnectionStrings:SupabaseConnection" "postgresql://postgres.xxxx:PASSWORD@aws-0-....pooler.supabase.com:5432/postgres"
   ```
3. شغّل الخادم. في السجل يظهر `قاعدة البيانات: PostgreSQL ...` والشارة في اللوحة تصبح خضراء.

- **الجداول تُنشأ وتُكمَّل تلقائياً** عند التشغيل (الجداول والأعمدة الناقصة فقط، بدون حذف أي بيانات). لا حاجة لتشغيل `supabase/schema.sql`.
- **تُعبّأ بيانات المول الأساسية تلقائياً مرة واحدة** عند أول تشغيل: المتاجر (15 متجراً) وأسماؤها البديلة في الفواتير، قواعد النقاط، المكافآت، البانرات، الحملات ومضاعفات النقاط. بعد ذلك تُدار بالكامل من اللوحة، ولا يُعاد إنشاء ما تحذفه.
- **لا تُضاف بيانات تجريبية** (عملاء أو فواتير وهمية) إلى القاعدة الحقيقية. إذا لم يوجد مدير عام يمكنه الدخول، يُنشأ الحساب `admin` وتظهر كلمة مروره **مرة واحدة** في سجل الخادم — غيّرها من صفحة طاقم العمل.
  (لتحديد كلمة المرور بنفسك: `dotnet user-secrets set "Bootstrap:AdminPassword" "..."` قبل أول تشغيل. وضع التعبئة يتحكم به `"SeedData"`: `Catalog` (الافتراضي مع قاعدة حقيقية) أو `Demo` أو `None`.)
- **حماية Supabase**: عند كل تشغيل يُغلق الخادم واجهة Supabase العامة (أدوار `anon`/`authenticated`) ويفعّل RLS على كل الجداول، فلا يمكن قراءة البيانات أو تعديلها إلا عبر الـ API. لذلك نموذج `mobile-app` القديم (React) الذي يتصل بـ Supabase مباشرة **متوقف ولا يُستخدم**؛ التطبيق الرسمي هو Flutter.
- إذا تعذّر الاتصال يتوقف الخادم برسالة واضحة بدل أن يعمل بقاعدة غير جاهزة.

## ⚠️ قبل التشغيل الفعلي
- غيّر `JwtSettings:Secret` وضعه عبر user-secrets أو متغيرات البيئة.
- غيّر كلمات مرور الحسابات التجريبية إن كنت قد فعّلت البيانات التجريبية.
